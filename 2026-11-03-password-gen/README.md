# 密码铸造厂 · Password Forge

> Day 05 · 2026-11-03

## 解决什么问题

网上的密码生成器大多有两个隐患：**要么后端生成（你的密码经过了别人的服务器）**，**要么用 `Math.random()`（不是密码学安全的随机数）**。

这个工具解决这两点：纯本地单文件运行，随机源用浏览器的 `crypto.getRandomValues()`，密码从不离开你的机器。

除了生成，它还会**把密码强度翻译成人话**——不是给你一个模糊的"强/中/弱"，而是直接告诉你"离线爆破需要多少年"。

## 怎么用

**方式一（推荐）**：直接用浏览器打开 `index.html`，双击即可，无需服务器。

**方式二**：起个本地服务

```bash
cd 2026-11-03-password-gen
python3 -m http.server 8931
# 打开 http://127.0.0.1:8931/
```

### 操作说明

| 控件 | 作用 |
|------|------|
| 长度滑块 | 6 ~ 64 位 |
| 字符集四选 | 小写 / 大写 / 数字 / 符号，可任意组合 |
| 排除易混字符 | 剔除 `0 O 1 l I \|`，适合要手抄/口述的场景 |
| 每类至少一个 | 强制四类字符各出现至少一次（应对"必须含大写和符号"的密码策略） |
| 可读音节模式 | 辅音+元音交替，生成能读出来的密码，好记又好打 |

## 实现要点

### 1. 密码学安全随机数 + 拒绝采样

`crypto.getRandomValues()` 返回 32 位无符号整数。最直观的取字符方式是 `arr[0] % pool.length`，但当池子大小不能整除 2³² 时会引入**取模偏差**——池中前几个字符的概率会略高。

本工具用拒绝采样消除这个偏差：

```js
var limit = Math.floor(0xFFFFFFFF / max) * max;
for (;;) {
  crypto.getRandomValues(arr);
  if (arr[0] < limit) return arr[0] % max;   // 只有落在整除区间内才采用
}
```

### 2. Fisher-Yates 洗牌

"每类至少一个"的实现是先强制塞入每类的代表字符，再补齐剩余位。但这样必填字符会固定排在开头——所以最后必须洗牌：

```js
for (var i = chars.length - 1; i > 0; i--) {
  var j = randInt(i + 1);
  var t = chars[i]; chars[i] = chars[j]; chars[j] = t;
}
```

注意 `randInt` 用的也是上面的拒绝采样版本，而不是 `Math.random()`。

### 3. 熵的计算与呈现

熵 = `长度 × log₂(字符池大小)`。比如 20 位、全字符集（26+26+10+29 = 91 个字符）：

```
20 × log₂(91) ≈ 130.2 bit
```

爆破时间按 `2^熵 / 2 / 10^10` 估算（假设攻击者每秒尝试 100 亿次，现代 GPU 集群量级），再用 `humanTime()` 转成"年 / 天 / 小时"这种能看懂的单位。

**注意**：这只是理论下界。如果密码被复用、被社工猜中、或者被键盘记录器抓走，熵再高也没用。

### 4. 可读音节模式

辅音表 `bcdfghjkmnpqrstvwxz` 与元音表 `aeiou` 交替拼接，每 6 个字符插一个数字、每 8 个插一个符号。生成结果如 `febido3quxa`，比随机串好记得多，代价是熵降低（字符池实际变窄）。

因此该模式与"每类至少一个"互斥——两者同时开会让约束变得难以满足。

## 已知限制

- **可读音节模式熵偏低**。页面显示的熵按全字符池计算，对可读音节模式是**高估**的，实际安全性弱于同长度的随机串。追求最高强度时请关闭该模式。
- **爆破时间估算基于纯暴力搜索**。真实攻击会先试字典、规则变形、泄露密码库，实际时间可能远低于显示值。
- **生成记录只存在页面内存中**，刷新即清空，不写 localStorage——这是刻意的，避免密码残留在磁盘上。
- 复制功能在 `file://` 协议下部分浏览器会限制 `navigator.clipboard`，代码已回退到 `document.execCommand('copy')`，但极老的浏览器仍可能失败。
- 未做密码短语（diceware）模式。

## 实测验证

### 独立反向校验（25/25 通过）

用 Python 复刻页面核心逻辑，并用独立方法校验输出。脚本：`/tmp/verify_pwd.py`

| # | 校验项 | 方法 | 结果 |
|---|--------|------|------|
| 1 | 长度与字符集约束 | 6 组配置逐一比对长度和字符归属 | ✅ 全部符合 |
| 2 | 排除易混字符生效 | 检查字符池 + 连续 50 次生成扫描泄漏 | ✅ 无泄漏 |
| 3 | 每类至少一个 | 500 次 `must=True` 生成，逐类检查 | ✅ 0 次违规 |
| 4 | 熵计算正确性 | 3 组与 `L×log₂(pool)` 手算比对 | ✅ 误差 < 1e-9 |
| 5 | 字符分布均匀性 | 卡方检验，60000 字符样本，df=88 | ✅ χ²=86.5 < 临界 124.1 |
| 6 | 唯一性 | 2000 次 24 位生成去重 | ✅ 2000/2000 唯一 |
| 7 | 爆破空间估算 | 3 组长度/池大小核对计算链路 | ✅ 正常 |
| 8 | HTML 结构 | 检查 CSPRNG、拒绝采样、洗牌、复制、离线 | ✅ 8 项全有 |

关键数据：卡方检验 χ²=86.5（df=88，α=0.01 临界值 124.1），字符频次实测 609~734，理论值约 674 —— 说明分布均匀，无取模偏差。
