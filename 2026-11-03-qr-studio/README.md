# 二维码工坊 · QR Studio

生成二维码的小工具。内容只在你的浏览器里算，**不上传任何服务器**，断网也能用。

## 解决什么问题

在线二维码生成站有三个老毛病：

1. **内容被上传** —— 网址、Wi-Fi 密码、vCard 名片全是明文发给别人的服务器
2. **强制跳转** —— 生成的码扫出来先到广告页，再跳去你的目标
3. **不能自定义** —— 想调颜色、留白、导出 SVG 就得注册付费

这个工具把这三件事都解决了：本地计算、扫出来就是你输入的原文、所有参数随便调。

## 怎么用

直接双击 `index.html` 就能跑，零依赖、零构建。

```
open index.html          # macOS
xdg-open index.html     # Linux
# 或者起个静态服务
python3 -m http.server 8000
```

能调的东西：

| 参数 | 说明 |
|---|---|
| 内容 | 网址 / 纯文本 / 中文 / 多行 vCard 都行 |
| 纠错等级 | L 7% · M 15% · Q 25% · H 30%（越高越抗污损，码也越密） |
| 前景 / 背景色 | 任意配色 |
| 留白边距 | 1–10 模块，默认 4（标准值） |
| 导出尺寸 | 128–2048 px |

导出支持 **PNG**（Canvas）和 **SVG**（矢量，放大不糊，适合印刷）。

## 实现要点

**内置 `qrcode-lib.js`**（Kazuhiko Arase 的 qrcode-generator 1.4.4，MIT 协议），不依赖 CDN，所以才能离线用。

**中文必须切 UTF-8** —— 这是最容易踩的坑，也是我实际踩到的：

```js
// 库默认的 stringToBytes 会做 c & 0xff，中文直接截断成乱码
// 不写这一行，中文二维码扫出来是 `}\x0cÙ/ 这种东西
qrcode.stringToBytes = qrcode.stringToBytesFuncs['UTF-8'];
```

**版本自动选择**：`qrcode(0, ecc)` 传 0 表示让库自己挑能装下的最小版本，用户不用关心 v1–v40。

**绘制思路**：先算 `总模块数 = 模块数 + 留白×2`，再算 `每模块像素 = floor(导出尺寸 / 总模块数)`。**必须向下取整**，否则会出现半像素导致边缘模糊、扫码器认不出。canvas 实际尺寸取 `总模块数 × 每模块像素`，可能略小于用户选的值。

**SVG 导出**用 `viewBox` + `shape-rendering="crispEdges"`，每个黑格子一个 `<rect width="1" height="1">`，无论放大到多少都不糊。

## 实测验证

用 Node 复现页面的绘制逻辑生成 PNG，再用 OpenCV 的 `QRCodeDetector` 反向解码，比对原文：

| 用例 | 纠错 | 结果 |
|---|---|---|
| `https://jiangyuxin.top` | M | ✅ |
| 中文「你好，这是一段中文测试内容」 | Q | ✅ |
| 长 URL（GitHub 仓库） | H | ✅ |
| 纯数字 16 位 | L | ✅ |
| 多行 vCard（含中文名） | M | ✅ |
| 留白 = 1 | H | ✅ |
| 留白 = 0 | H | ✗ 扫不出 |

**留白为 0 会扫不出**，所以滑块下限锁在 1，默认 4（QR 标准规定的最小静区）。

## 已知限制

- 留白低于 4 时，部分老旧扫码器（尤其微信在暗光下）识别率会降低，重要物料请保持默认
- 前景/背景对比度太低时扫不出，工具目前**不**自动校验对比度（下一步可加 WCAG 式的对比度检查）
- 不支持彩色渐变、LOGO 嵌入
- 内容过长时（超高纠错等级 + 长文本）会超出 v40 容量，此时会提示调低纠错等级
- `qrcode-lib.js` 是第三方库，`stringToBytes` 的 UTF-8 开关**必须手动打开**，别删
