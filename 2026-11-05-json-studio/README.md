# JSON 工坊 · json-studio

> Day 07 · 2026-11-05

粘贴一段 JSON，格式化、校验、看结构、转成 JS 对象、拍平成表格 —— 全程在浏览器本地跑，一个字节都不上传。

## 解决什么问题

日常开发里最烦的三件事，这里一次解决：

1. **拿到的 JSON 不合法**：从日志、聊天记录、配置文件里复制出来的 JSON，常带 `//` 注释、尾逗号、单引号、裸键（JSON5 / JSONC 写法），`JSON.parse` 直接炸，而报错只说「Unexpected token」不告诉你错在哪一行。
2. **数据结构看不明白**：嵌套五层的接口返回，人眼数不清；
3. **要把 JSON 塞进代码**：手动改成 JS 对象字面量太傻。

## 怎么用

双击 `index.html` 即可（零依赖、零构建、离线可用）。或者 `python3 -m http.server 8957` 后访问。

| 操作 | 说明 |
|---|---|
| **格式化** | `Ctrl/⌘ + Enter`。结果写回左侧并美化；输入是脏 JSON 时自动修复 |
| **压缩** | 输出单行，提示省了多少字符 |
| **转义为字符串** | 把整段 JSON 变成一行 `"{\"a\":1}"`，方便塞进 env / 代码字符串 |
| **去转义** | 反向：`"{\"a\":1}"` → 展开成 JSON |
| **缩进** | 2 空格 / 4 空格 / Tab / 不缩进 |
| **键排序** | 递归按键名升序（数组顺序不变） |
| **JS 对象字面量** | 输出 `{ name: 'x', list: [1,], }` —— 裸键 + 单引号 + 末尾逗号 |
| **来点示例** | 载入一段故意写坏的 JSONC，演示一键修复 |
| **打开文件 / 拖拽** | 载入本地 .json（≤5MB） |
| **复制结果** | `Ctrl/⌘ + Shift + C` |
| **下载 .json** | 把当前输出存成文件 |

右侧三个视图：

- **文本** —— 格式化结果，带语法高亮；
- **树形** —— 折叠展开（超过 20 个键的对象默认折叠），点击节点旁的路径可看取值；
- **路径表** —— 扁平化成 `路径 / 类型 / 值` 三列，点路径即复制。

**小惊喜**：在树形或路径表里点任意值，会弹出 **JSONPath 取值** 对话框，直接给你可粘进代码的路径和取值。树形视图里 `Alt + 点击` 对象节点也能直接拿到该节点的路径。

## 实现要点

- **`core.js` 零 DOM 依赖**，浏览器和 node 通用（同一份代码被 52 条 node 测试 + 页面同时使用）。
- **容错修复管线**（`repairParse`）：每一步修改后都重新 `JSON.parse`，成功即停并回报「改了哪几步」：
  改注释 → 去尾部多余分号 → 单引号转双引号 → 去尾逗号 → 裸键加引号 → 裸值加引号 → 智能引号 → 直引号。
  注释剥离与引号转换都是**状态机**实现，不会把 `"https://x"` 里的 `//` 当注释、也不会把 `'it\'s'` 里的 `'` 当结尾。
- **错误定位自己算**：新版 V8 的报错里已不再稳定给出 `position`，所以 `locateError()` 从引擎消息尾部的片段反推位置，再用逐字符扫描换算成行列号；页面左下角还会把出错那一行高亮。
- **自写高亮扫描器**：不认识关键字也不丢字符，输入到哪就高亮到哪（不合法时也不会闪成一片红）。
- **自写 `validate()`**：递归下降分词器，比 `JSON.parse` 的错误信息更有用（「对象的键必须是双引号字符串」「多余的尾逗号」「数字不能有前导零」），并用 400 条随机合法 JSON 与 `JSON.parse` 交叉比对过。
- **键排序不用原生 `JSON.stringify`**：V8 会把 `"2"`、`"10"` 这类整数键强制排到最前，破坏排序结果，所以排序模式用自写的序列化器按对象逐个排键。
- **高亮层叠在 `textarea` 背后**，`textarea` 文字设为透明只留光标，实现「一边输一边高亮」而不引入编辑器库。

## 已知限制

- 修复能力覆盖注释 / 单引号 / 尾逗号 / 裸键 / 裸值 / 智能引号；**不处理**缺少的引号、未闭合的括号、`+1` 这种显式正号。
- 超过 `Number.MAX_SAFE_INTEGER`（2^53-1）的大整数，`JSON.parse` 会丢精度，本工具如实显示被舍入后的值，**不做** BigInt 保留（会静默出错，不如不承诺）。
- 树形视图对超大规模数据（> 数万节点）会卡，建议用「路径表」或先压缩。
- 当前没有「按路径编辑」功能，只读。
- 没有做虚拟滚动，20MB 级文件不保证流畅。
