# 蛇形呼吸 · Snake

> Day 09 · 2026-11-07 · 游戏 / 纯前端零依赖

经典贪吃蛇，但不是把教程抄一遍就完事。

## 解决什么问题

**想在浏览器里玩一局手感对的贪吃蛇，又不想被广告和「请下载 App」拦住。**

双击 `index.html` 就能玩，断网也能玩，输赢数据全在你自己电脑上。

## 怎么玩

- **方向**：`↑ ↓ ← →` 或 `W A S D`；手机端有虚拟方向键，也可直接在棋盘上滑动
- **暂停**：`空格` 或 `Esc`（切到别的标签页会自动暂停）
- **重开**：`R`，或结束时直接按任意方向键
- **🤖 教练**：开启后蛇头会冒出青色箭头，那是 BFS 算出的「到食物的最短路径方向」。它只找最短路，**不保证不撞墙**，当参考别当自动驾驶（见下方实测数据）
- **🌀 穿墙**：开启后从一边出去、对面进来，边框会变青色虚线。难度立刻变低，但撞自己照样死
- 吃得越多，每格移动间隔越短：`170ms → 70ms` 封顶

## 实现要点

### 1. 引擎与渲染彻底分离

`core.js` 是不碰 DOM、不碰 canvas、不读 `Date.now()` / `Math.random()` 的纯函数模块：

- `createGame({cols, rows, rng})` — 随机源可注入，所以测试是确定性的
- `step(state, {wrap})` — 推进一格，返回 `{moved, ate, died, won, reason, wrapped}`，**不 mutate 之外无副作用**
- `queueDir(state, dir)` — 转向排队，做合法性判定
- `bfsFirstMove(state)` — BFS 最短路的第一步方向

浏览器里挂 `window.SnakeCore`，node 里 `module.exports`，同一份代码两边跑。

### 2. 「一 tick 只能转一次」的真实陷阱

朴素实现写着「不能 180° 掉头」，判断依据是 `state.dir`。**这是错的**：

```
当前向右(right) → 玩家同一帧内按 up → 按 down
若判据是 dir：up 合法(pending=up)，down 对 dir=right 也合法 → pending=down
下一 tick 执行 down，而 head 刚从 right 走来的方向是 left……不会死？
```

更阴间的变体：`dir=right`，同一帧按 `up` 再按 `left`：up 合法后 pending=up，若判据仍是 dir(right)，left 不反向于 right 于是合法 → pending=left。但实际推进时上一格在左，直接咬尾巴。

**修法：反向判定必须基于 `pendingDir`，而不是 `dir`。** 这一条在 `test-core.js` 的「禁止 180 度掉头」组里有对应用例。这个 bug 是在写页面层测试时被抓出来的（`ArrowDown` 之后按 `ArrowUp` 竟然生效），属于典型的「逻辑单测绿了、交互测试红」案例。

### 3. 穿墙作为引擎参数，而不是页面 hack

第一版在 `app.js` 里试图「step 判死后撤销再手动折返」，代码里出现 `shift()` 后又 `unshift()` 的补丁式回滚，很容易出现状态不一致。重构后把 `wrap` 下推到 `step(state, {wrap:true})`：坐标用取模折返，`ev.wrapped` 告知渲染层「这一步跨了边界」。撞墙判定只在 `!wrap` 时执行。

### 4. 视觉

- 蛇身**呼吸光波**：亮度沿身长按 `sin(t/260 - i*0.55)` 传播，看着像一束光从头流向尾巴
- 食物是带脉冲的径向渐变果冻球 + 外光晕
- 吃到食物爆 14 个粒子 + `+10` 飘字
- 死亡时棋盘红闪 + 屏幕抖动
- 音效全用 WebAudio 现场合成（吃食物三音上行、死亡下滑锯齿波），**零素材文件**

## 已知限制

- **AI 教练只是贪心 BFS 最短路**，不做「吃了这颗会不会把自己困死」的安全评估。实测 200 局自动驾驶全部撞墙死，平均 35 分 —— 所以它叫「教练」不叫「外挂」
- 最高分记录在 `localStorage`，换浏览器/清缓存就没了
- 棋盘固定 20×20，不随屏幕变化（为了让不同设备的手感一致）
- 没有存档/读档
- 触摸滑动在极小的屏幕上可能与页面滚动冲突（已设 `touch-action:none` 缓解）

AI 自动驾驶真实输出：

```
=== AI 自动驾驶 200 局（15×15）===
总局数        : 200
平均分        : 350.8
最高分        : 640
平均吃掉        : 35.1
死因统计      : {"wall":200,"self":0}  通关: 0
不变量违反次数  : 0
```

> 死因全是 `wall` 这件事本身是个有意思的结论：纯 BFS 最短路会径直冲向边界上的食物，
> 到了边上却不知道要提前拐。想做更强的 AI 得加「模拟吃完后是否仍有通路」的安全启发。
