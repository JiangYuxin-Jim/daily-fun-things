# 今词 · 每日猜词（wordle）

> Day 11 · 2026-11-09

一个纯前端 Wordle 变体：6 次机会猜出 5 个字母的英文单词。每天一题、全球同题，另带自由练习与困难模式，外加一个**会算信息熵的 AI 教练**。

零依赖，单页 HTML + 三个 JS 文件，双击 `index.html` 就能玩。

## 解决什么问题

原版 Wordle 每天只能玩一次，玩完就没事干了。这个版本把「一次性每日题」扩成三种玩法，并且把「卡住时该怎么办」做成了可计算的：提示按钮不是随便给个答案，而是在全部合法词里挑**期望剩余候选数最小**的那一个。

## 怎么玩

```bash
cd 2026-11-09-wordle
python3 -m http.server 8937
# 打开 http://127.0.0.1:8937
```

也可以直接双击 `index.html`（不依赖任何网络资源）。

**规则**

- 每猜一个 5 字母词，格子给出反馈：
  - ⬛ 灰 = 这个词里没有该字母
  - 🟨 黄 = 有这个字母，但位置不对
  - 🟩 绿 = 位置完全正确
- 字母重复时按**真实数量**结算：答案里只有一个 E，你猜了两个 E，只有一个会亮黄/绿。
- **每日挑战**：6 次机会，当日答案由日期哈希决定，所有人一致，计入连胜。
- **自由练习**：随机出题，8 次机会，不计战绩。
- **困难模式**：已经确认的字母（绿位 + 黄位）下一手必须用上，否则拒绝提交。

**AI 提示**：点 💡 会给出当前信息量最大的候选词，并显示「剩余候选 N」。每日 2 次、练习 3 次，不消耗猜词次数。

**复制战绩**：结算面板可以把整局结果复制成 🟩🟨⬛ 色块，直接粘到聊天里。

## 实现要点

### 1. 评分：两遍扫描，正确处理重复字母

这是 Wordle 最容易写错的地方。朴素做法是对每个字母查 `answer.includes()`，会在 `poppy` vs `apple` 这类重复字母的场景报错。

```
第一遍：逐位比对，绿位标记 CORRECT，被吃掉的字母从池子里扣掉
第二遍：非绿位查池子，还有剩 → PRESENT，并再扣一个
```

实测 `scoreGuess('poppy', 'apple') === [1,0,2,0,0]`：索引 2 的 `p` 与答案同位 → 绿；索引 0 的 `p` 抢到唯一一个 `p` → 黄；索引 3 已无余量 → 灰。

### 2. 困难模式的数量下限推导

直觉写法是按「每行黄+绿数取最大值」，但在跨轮场景下会低估。正确做法是把**已确定的绿位占用**和**该行黄+绿总数**合并考虑，取能同时满足二者的最小数量。

### 3. AI 教练：熵最小化 + 模式矩阵

- 把评分压成 **10 bit 整数模式码**（每位 2 bit：0 灰 / 1 黄 / 2 绿），字符串比较 → 整数比较。
- 预构建 `1062 × 817` 的 `Uint16Array` 模式矩阵（≈1.7 MB），熵计算从「每次重新评分」变成「查表 + 1024 桶直方图」。
- 字母计数用**版本号惰性清零**（`REM_VER`/`REM_GEN`），省掉热循环里的 26 次清零写入。

**优化前后对比（同一台机器，`node`）**

| 阶段 | 优化前 | 优化后 |
|---|---|---|
| 865k 次全量评分 | 874 ms | 391 ms |
| 首次提示建议 | 13328 ms | 315 ms |
| AI 单局自动求解 | 18071 ms | 496 ms |

首轮提速约 42×，提示从「点一下愣十几秒」变成「立刻出结果」。

### 4. 每日题确定性

```js
hashStr('2026-11-09' + '|jinzi') → mulberry32 种子 → ANSWERS[floor(rng() * n)]
```

同一天任何人、任何设备算出同一个答案；不依赖服务器。

## 已知限制

- 词库是手工整理的 817 个答案 + 1062 个合法猜测，**不是完整英文词典**。输入词库外的词会被拒（会提示「词库里没有 XXX」）。
- 答案池偏向常见名词/形容词，冷僻词覆盖不足。
- 首次点击提示会有约 0.3s 的矩阵构建（浏览器里通常更短），之后同一会话内复用。
- 战绩数据存在 `localStorage`，换浏览器/清缓存即丢失。
- 不支持 6/7 字母变体（评分函数按 5 位硬编码）。
