# 雷区 · 扫雷（minesweeper）

> Day 12 · 2026-11-10

经典扫雷的现代复刻：三档难度、首手 100% 安全、右键插旗、双击数字快速展开（chord），
外加一个**只会说谎的**提示系统——它只告诉你逻辑上 100% 确定的事，绝不让你赌运气。

零依赖，单页 HTML + 两个 JS 文件，双击 `index.html` 就能玩。

## 解决什么问题

原版扫雷最劝退的点不是雷多，而是"这一格到底要不要赌"。很多"提示"功能其实是作弊——直接告诉你答案。
这个版本把提示做成一个**约束求解器**：把每个已揭开数字格看成一个"这些邻格里恰好有 N 个雷"的方程，
能推出来的才给你，推不出来的老实说"该猜了"，并挑一个风险期望最低的格子。

## 怎么玩

```bash
cd 2026-11-10-minesweeper
python3 -m http.server 8931
# 打开 http://127.0.0.1:8931
```

双击 `index.html` 也可以（不依赖任何网络资源）。

**操作**

| 操作 | 效果 |
|---|---|
| 左键 / 单击 | 翻开格子 |
| 右键 / Ctrl+单击 / 手机长按 | 插旗 / 取消旗 |
| 左键点已揭开的数字 | 若周围旗数 == 数字，自动翻开其余邻格（chord） |
| `R` | 重开 |
| `H` | 提示 |

**难度**

- 初级 9×9 / 10 雷
- 中级 16×16 / 40 雷
- 高级 16×30 / 99 雷

**首次点击**：及其 8 邻域保证无雷，所以第一下永远不会摔死（如果地图不够大放雷，则退化到只保护点击格）。

## 实现要点

### 1. 状态用扁平 typed array

棋盘是 `Int8Array`，一字节一格：

- `0..8` = 已揭开，值就是周围雷数
- `9` = 未揭开
- `10` = 已插旗

雷位另用 `Uint8Array` 存。这样"是否已翻开"的判定是 `v >= 0 && v <= 8`，一次比较，
flood fill 时也不用在对象数组里跳来跳去。

### 2. 首手安全靠延迟布雷

不在开局就布雷，而是第一次 `reveal()` 时才布：把点击格 + 8 邻域剔除，剩下格子里 Fisher-Yates
洗出 `mines` 个位置。这样首手必定踩空，同时避免了"开局没有任何数字格"的尴尬。

### 3. Flood fill 用显式栈

展开 0 格时不会递归爆栈：`while (stack.length) { pop; 记数字; 为 0 则把未揭开的邻格压栈 }`。
高级难度一次性展开几百格也不会卡。

### 4. 提示求解器：单格约束 + 两格子集推断

```
对每个已揭开的数字格 d：
    flags = d 周围旗数,  un = d 周围未揭开格
    rem = d - flags
    rem == 0       → un 全安全
    rem == len(un) → un 全是雷
    否则记为约束 (un, rem)

对每对约束 A ⊂ B：
    d = B.rem - A.rem
    d == 0            → B\A 全安全
    d == len(B\A)     → B\A 全是雷
```

这就是经典扫雷玩家脑子里那套"1-2-1 模式""1-1 贴边"推理的形式化版本。推不出来时退化为
"邻接数字约束下的最小风险格"，并把这条路径明确标注为该猜了。

`🧠 自动插旗` 按钮会反复调用求解器，把所有能 100% 确定的雷一次性插完——它不会猜。

### 5. 成绩记录

通关用时存 `localStorage`（key `minecraft.best`，按 `行x列_雷数` 分档），结算面板展示个人最佳。

## 已知限制

- 提示的"最低风险格"是启发式（邻格约束平均雷密度），不是精确概率；真正要精算需要枚举所有
  连通边界格的雷分布（类似 CSP 计数），没做。
- 求解器只做到"两格子集推断"，没有做全局枚举 / 概率求解，所以部分逻辑可解的残局它会报"该猜了"。
- 自动插旗只处理确定的雷，不会自动翻开确定的空格（要翻可以点提示）。
- 没有实现"问号旗"标记和自定义尺寸。

## 实测验证

```
$ node --check core.js && node --check app.js     # 通过
$ node test.js
✅ pass=39 fail=0
```

测试覆盖（`test.js`，39 项）：

- 棋盘初始化 / 尺寸 / 初始全隐藏
- **首手安全**：5 个不同起始格，点击后其 3×3 邻域无雷
- 雷数精确性（16×16 / 40 雷实际布了 40 个）
- 插旗 → 取消旗 → 剩余雷数联动
- 踩雷判负并记录 `explodedAt`
- flood fill 会扩散，且首手格本身无雷
- **所有已揭开数字格的数值与真实雷位逐一比对一致**
- 求解器跑 200 局 9×9 / 10 雷，通关率 ≥ 85%（纯逻辑推断 + 必要猜测）
- 纯逻辑可解局数 ≥ 10%（说明求解器确实在推理，而不是全靠猜）
- 胜利后自动补旗，旗数 = 雷数，且终局不可再操作
- chord：插满旗后点数字格能翻开剩余邻格
- `rng` 同种子可复现（测试可复现）
- 雷数 ≥ 格子数时抛错
- 性能：50 局 16×16 / 40 雷全自动求解 < 5 秒

网页侧：`python3 -m http.server 8931` 起服务，`index.html` / `core.js` / `app.js` 均返回 200；
静态校验 `app.js` 中引用的 14 个 DOM id 全部存在于 `index.html`，`core.js` 先于 `app.js` 加载。
