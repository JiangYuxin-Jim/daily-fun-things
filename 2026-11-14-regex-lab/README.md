# 正则实验室 · regex-lab

> Day 16 · 2026-11-14

## 解决什么问题

写正则时最烦的三件事：

1. **报错看不懂** —— 浏览器只甩一句 `Invalid regular expression: /(/: Unterminated group`，你还得猜是哪里少了括号。
2. **写完心里没底** —— 这条正则跑在长文本上会不会卡死？`(a+)+$` 这种回溯炸弹，测试数据短的时候完全看不出来。
3. **别人（或三个月后的自己）看不懂** —— `(?<=\$)\d+(?:\.\d{2})?` 到底是啥意思，一层层拆才明白。

这个工具把这三件事一次解决：**实时高亮匹配 + 中文报错 + 中文结构解释 + 回溯风险体检 + 可点即用的片段库**，纯本地、零依赖、不联网。

## 怎么用

```bash
# 方式一：直接双击打开
open index.html          # macOS
xdg-open index.html      # Linux

# 方式二：起个本地服务（推荐，避免个别浏览器的 file:// 限制）
cd 2026-11-14-regex-lab
python3 -m http.server 8932
# 浏览器打开 http://127.0.0.1:8932
```

操作：

- 顶部输入框敲正则，中间的 `gimsuy` 直接填标志位；下面一排小胶囊也可点选开关。
- 左边贴测试文本，右边即时看到高亮和捕获组表（点「匹配预览」区域可滚动查看）。
- 下方三个标签页：
  - **体检**：回溯风险预警（红色=危险、黄色=可疑），每条都给修改建议。
  - **解释**：把正则按 token 逐层翻译成中文，缩进表示分组层级，并解释 g/i/m/s/u 的作用。
  - **片段库**：18 条常用正则（邮箱、手机号、URL、日期、Markdown 链接……），点一下连示例文本一起灌进去。
- <kbd>Ctrl</kbd>+<kbd>Enter</kbd> 强制立即重算（平时输入是 120ms 防抖）。

## 实现要点

- **匹配执行借力原生引擎**：`engine.js` 用 `new RegExp(pattern, flags)` 跑真实匹配，保证语义 100% 和 JS 原生一致——自己手写一个回溯引擎很容易在零宽断言、反向引用上出偏差，反而坑用户。
- **静态扫描器 `scan()`**：手写 tokenizer，把正则拆成 `char / class / dot / anchor / quant / open / close / alt / backref / escape` 十类 token，记录分组深度、量词上下界与贪婪/懒惰/占有模式。这是「中文报错」和「结构解释」的共同数据源。
- **回溯风险启发式 `riskScan()`**：核心规则是「外层无界量词包住内层量词」→ 指数级回溯预警；另外识别「同字符类连写两次」「量词紧跟量词」等可疑写法。
- **中文报错 `translateError()`**：14 条 V8 英文报错 → 中文的映射表（`Unterminated group` → 分组没有闭合……），原文保留在第二行方便搜索。
- **高亮分段 `segment()`**：把原文切成 `{text, hit}` 片段，命中片段用三种下划线颜色轮换，超过三处也不会看花眼。
- **浏览器/Node 双用**：`engine.js` 末尾把 `module.exports` 挂到 `window.REGEX_LAB`，所以同一份代码既能被 `test.js` require，又能被 `index.html` 直接 `<script>` 引入。

## 已知限制

- 匹配由浏览器原生引擎执行，所以**不做「步数上限」保护**——真给足 `(a+)+$` + 30 个 a 的输入，页面会卡几秒。体检页会在执行前就把它标红警告，但不会强制拦截。
- 静态体检是**启发式**，会有误报/漏报，不等于形式化验证。
- 解释器按 token 线性展开，同一个分组内嵌套多层时缩进会比较深，但不折叠。
- 捕获组位置（`start/end`）对重复出现的子串是近似定位（原生接口不直接暴露子组偏移）。
- 不支持 `\p{…}` 之类需要特定构建的语法以外的扩展（如 `x`/自由空白标志）。
- 移动端可用但输入框偏窄，建议桌面使用。
