# 流程铸造间 · flow-forge

> 拖几个方块，画出一条 Agent 工作流；点一下「试跑」，看它怎么走、烧多少 token、每月多少钱。
> 纯前端、零依赖、断网可用。

## 解决什么问题

现在人人都在搭 Agent，但工作流一复杂就看不清了：这条链到底跑几步？哪条分支会被跳过？
要花多少 token？一个月得烧多少钱？有没有哪个节点永远走不到？

flow-forge 把这件事变成画板：**节点可拖、可从右边缘拉线连起来、可填 token 成本**，
然后一键试跑，把「执行顺序 / 跳过分支 / 关键路径 / 最大并行宽度 / token 与月度费用」全部算给你，
再顺手做一次结构体检（环、孤儿节点、悬空出口、单分支条件……）。

## 怎么玩

直接用浏览器打开 `index.html`（零构建、零依赖）。

1. 左边调色板点一下加节点：**开始 / 大模型 / 工具调用 / 条件分支 / 人工确认 / 结束**
2. 拖节点摆位置；**从节点右边缘往另一个节点拖**即连一条边
3. 右侧「节点」页签可改标题与 token 估算（LLM 有输入/输出两栏，工具是返回 tokens）
4. 条件节点的两条出边会自动标成 `是` / `否`；在「节点」页签里选试跑走哪边
5. 点 **▶ 试跑**：看 token 总量、执行顺序、跳过节点、关键路径、并行宽度，以及 5 个模型的月账单
6. 点 **🔍 体检**：结构问题清单（error / warn / info）
7. **⤓ Mermaid** / **⤓ JSON** 复制导出，粘到 Notion、GitHub、mermaid.live 都能渲染
8. 右上角下拉框有三个内置示例（客服知识助手 / 日报自动生成 / 反例：自嗨 Agent）

快捷键：选中节点后 `Delete` 删除；点空处取消选中。

## 实现要点

- **纯函数内核**（`engine.js`）：图 → Kahn 拓扑排序 → 分支路由模拟 → 执行追踪 → 统计 → 费用。不碰 DOM，Node 和浏览器同一份代码。
- **分支不只看拓扑序**：条件节点执行时给每条出边打上「选中/未选中」标记，下游节点若只靠一条「未选中」的边进来就被判为跳过——所以试跑会真的跳过整条死分支，而不是把所有节点都跑一遍。
- **关键路径与并行宽度**：按最长链算关键路径（绕回的分支不会被误算成终点），按层级算最大同时执行数，直接告诉你「这条流程能不能并行提速」。
- **零配置画布**：手写 Canvas 渲染，贝塞尔曲线连边、箭头、条件标签、token 角标、跳过节点虚线变灰，选中/悬停高亮，无任何图形库。
- **示例本身是测试用例**：`sample.js` 的三张图分别覆盖「分支跳过」「并行取数」「环形反例」，`test-sample.js` 用它们断言引擎行为。

## 已知限制

- 布局是手动拖拽，没有自动排版；节点多了需要自己摆（示例图已摆好）。
- 连线只能从「右边缘出口」拖到节点本体上，不支持从入口反向拖、也不支持拖到空白处再吸附。
- 条件节点最多自动区分两条出边（是/否），三条以上分支需要手动改 `cond` 字段后导入 JSON。
- 费用按 100 次/天、30 天外推，不含缓存命中折扣与批处理优惠。
- token 估算靠手填的默认值，不是真实分词器计数（要精确计数可搭配同项目的 token-cost）。
- 不做真实执行：试跑是「结构模拟」，不会真的调模型或工具。

## 注记：一个诚实的 bug 记录

最初 `widthOf()` 把「所有节点中最晚的收尾时刻」当关键路径，遇到带回流边的图会把回流段也算进去，
导致「日报」示例的关键路径虚高。现在改为：**深度 = 入口到「无出口节点」的最长链**，
宽度单独用全部节点的收尾时刻计算。`test.js` 的并行图断言（depth = 3、width = 2）依旧全绿，说明改动没有破坏线性/并行图的语义。

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面与交互（Canvas 画布、属性面板、试跑/体检/导出） |
| `engine.js` | 纯函数内核：拓扑、分支模拟、统计、费用、lint、Mermaid 导出 |
| `sample.js` | 三张内置示例图（纯数据） |
| `test.js` | 引擎自检（44 项断言，含 150 轮随机图重放） |
| `test-sample.js` | 示例图行为自检（13 项断言） |
| `check-page.js` | 页面资源与 DOM 钩子检查 |
