# 今天吃什么 · 决策转盘

一个帮你结束「今晚吃啥」拉锯战的本地转盘：候选菜单随手加，每个菜可以设权重，
转一下让转盘替你拍板，最后还会丢一句口味点评。

## 解决什么问题

- 每天要做的第一个决定往往不是工作，而是「吃什么」。选择越多越难选。
- 摇骰子式的随机太冷，转盘带视觉与可解释性：你能看见每个候选的「势力范围」。
- 想让它稍微偏心（比如「今天更想吃面」），就给面加权重，而不是靠意志力。

## 怎么用

1. 双击 `index.html`（或 `python3 -m http.server` 起静态服务）就能用，零依赖、零网络。
2. 右侧「候选菜单」里输入菜名回车（或点「加入」）即可添加，上限 24 项。
3. 每个菜单项右侧的下拉框是**权重 1×~9×**。权重越大，被抽中的概率越高；权重 >1 的扇区在转盘上会标出 `×N`。
4. 点「转 一 下」或按空格键开转（输入框内按空格不会触发）。
5. 转完给出结果 + 一句口味推荐语，并播放一个短促的「叮」提示音（Web Audio 实时合成，无音频文件）。
6. 底部按钮：「恢复默认」回到内置 8 项菜单；「清空」从头开始；「随机权重」把权重洗一遍，防止菜单一直偏。
7. 所有修改自动存到 `localStorage`，下次打开还是你的菜单。

## 实现要点

- **`wheel.js`** 是纯逻辑引擎（不碰 DOM），浏览器下挂到 `window.FoodWheel`，Node 下 `module.exports`，所以核心算法可以脱离浏览器自测。
  - `addItem` 做空白归一 + 大小写不敏感去重 + 长度/数量上限校验，返回 `{ok, items, reason}` 而不是抛异常。
  - `pickIndex` 按权重累加抽签，权重直接被夹在 1~9，浮点误差有兜底。
  - `spinTo` 计算最终绝对旋转角度：`圈数 × 360 + 扇区中心角 ± 40% 扇区宽的抖动`，保证指针落点在目标扇区内但每次位置不完全一样。
  - `itemAtPointer` 是 `spinTo` 的逆运算，用于验证落点是否自洽（自测里跑了 5000 次）。
- **视觉**：单个 `<canvas>` 绘制扇区，旋转交给 CSS `transform: rotate()` 由合成器处理，60fps 无重绘压力。
  缓动曲线 `easeOutQuart`，先快后慢，末尾自然减速。
- **配色**：24 色数组循环，`shade()` 生成径向渐变让每个扇区有轻微体积感；标签文字过大会自动截断加省略号。
- **标签体系**：内置池带 `tag`（热辣/汤面/下饭/省钱/浓郁/家常/管饱/约人），结果页据此给出不同点评，未知标签有兜底文案。
- **安全**：所有写入 DOM 的用户文本都走 `esc()` 转义。

## 已知限制

- 转盘扇区宽度是**等宽**的，权重只影响概率，不影响视觉面积（视觉上靠 `×N` 角标提示）。这样转盘更好看也更好读，但「面积 = 概率」的直觉不成立。
- 只支持中英文文本，未做日韩文竖排/长词断行优化。
- 历史记录没做，转完的结果不落盘（只有菜单会保存）。
- 需要浏览器支持 Canvas 与 `aspect-ratio`（现代浏览器均可）。

## 实测验证

- `node --check wheel.js` 通过。
- `node test.js` 全部 19 项断言通过，关键几项：
  - 8 项默认池载入；重复项（含前后空白）被拒；空名、超长名被拒。
  - 权重分布实测：权重 6/3/1 三项 30000 次抽样分别为 **60.7% / 29.1% / 10.2%**，与理论 60%/30%/10% 吻合。
  - `spinTo` → `itemAtPointer` 闭环 5000 次，落点与选中项 **0 次不一致**。
  - 扇区覆盖 0~360 无缝隙；少于 2 项时拒绝开转。
- `python3 -m http.server 8934` 起静态服务，`index.html` 与 `wheel.js` 均返回 **200**。
